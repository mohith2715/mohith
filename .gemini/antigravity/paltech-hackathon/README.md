# Ideas Management System

An end-to-end web application for submitting, reviewing, and tracking organizational ideas, built using Node.js, Express, SQLite, and Stitch MCP.

## Setup and Run Instructions

1. **Install Dependencies:**
   ```bash
   npm install
   ```

2. **Run the Development Server:**
   ```bash
   npm run dev
   ```

3. **Run Tests:**
   ```bash
   npm test
   ```

4. **Access the App:**
   Open `http://localhost:3000` in your browser.
   - **Submitter Account:** Register a new account via the UI.
   - **Reviewer Account:** 
     - **Pre-seeded:** `reviewer@example.com` / `reviewer123`.
     - **Manual Creation:** During registration, use the secret code `REVIEW_2024` in the "Reviewer Code" field to assign yourself the Reviewer role.

## Tech Stack and Rationale

*   **Backend:** Node.js with Express. Chosen for its simplicity and robust middleware ecosystem.
*   **Database:** SQLite (`better-sqlite3`). Selected to fulfill the local persistence requirement with zero-config infrastructure.
*   **Authentication:** `express-session` with `bcrypt` password hashing. Ensures secure, stateful sessions.
*   **Frontend UI:** Generated using **Stitch MCP**. Static designs were hydrated via vanilla JavaScript (`app.js`) to provide a dynamic Single Page Application (SPA) feel while maintaining a clean separation of concerns.
*   **Testing:** Jest and Supertest for comprehensive API and logic verification.

## Architecture Overview

The system follows a modular architecture:
1.  **Frontend (`public/`):** Vanilla JS hydrates HTML templates generated by Stitch MCP. Custom logic in `app.js` handles dynamic rendering, state management (tabs, pagination), and custom UI components like the confirmation modal.
2.  **API (`routes/`):** Decoupled authentication and idea management routes. Implements strict Role-Based Access Control (RBAC).
3.  **Persistence (`database.js`):** Centralized SQLite connection and schema management. Enforces data integrity through foreign keys and unique constraints.

## Key Features & Design Decisions

*   **Custom Confirmation Modal:** Replaced native `window.confirm` with a custom HTML/CSS modal to resolve cross-browser inconsistencies and prevent event bubbling conflicts with card navigation.
*   **UPSERT Rating Logic:** Allows users to update their existing ratings seamlessly without duplicating counts, improving UX over a simple "already rated" error.
*   **Reviewer Secret Code:** Provides a secure path for designated personnel to create Reviewer accounts without needing manual database seeding for every new instance.
*   **Event Propagation Management:** Robust handling of nested click events (Delete vs. Card Navigation) using `stopPropagation`, `preventDefault`, and a global `modalOpen` state.

## How AI Tools Were Used

*   **Stitch MCP:** Used to generate high-fidelity UI screens that align with professional design standards.

## Assumptions

*   A user can only rate an idea they did not submit.
*   Ideas become immutable (edit/delete disabled) once they reach "Selected" or "Rejected" status.
*   "Reviewer Code" is a shared secret for this organizational prototype.

## Trade-offs

*   **Vanilla JS vs Framework:** Used Vanilla JS to maintain the purity of the Stitch-generated HTML while adding dynamic behavior, avoiding the build-step overhead of React for this specific scope.
*   **SQLite:** Perfect for a local prototype/hackathon but would require migration to PostgreSQL for high-concurrency production environments.
